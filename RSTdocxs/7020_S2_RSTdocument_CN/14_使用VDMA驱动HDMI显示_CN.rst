Using VDMA to Drive HDMI Display
===================================

**The Vivado project for this experiment is "vdma_hdmi_out".**

Our board has an HDMI interface. We have previously introduced how to implement HDMI display using the PL side. But how can we use PS to control HDMI display content? Since the PS does not have an integrated display control system, we still need to rely on the PL for implementation. How do we transfer data to the display section on the PL side? This requires the data exchange interface between PS and PL. Typically, the high-performance HP port is chosen for high-speed data transfer between PS and PL. The HP port has a maximum data width of 64 bits, and if the frequency runs at 150MHz, the bandwidth can reach 9.6Gbps, which is sufficient for image data transfer.

There are many data transfer solutions, but they all rely on the DMA system. The DMA system can transfer display data from DDR3 to the display, reducing CPU overhead. VDMA is a specialized DMA developed by Xilinx specifically for video input and output, and is an important topic when learning Xilinx
FPGA video processing.

In the previous experiment, the HDMI display data was generated internally by the PL. In this experiment, the display data is generated by the PS, and then the PL sends it to the HDMI interface through VDMA.

1) Create a new project named "vdma_hdmi_out" based on "ps_hello". Open the ZYNQ configuration. Since we need to read data from DDR, we use the high-performance HP port for data exchange between PS and PL. Enable the HP0 interface.

~~~~~~~~~~~~~~~~~~~~~

2) Enable I2C0 and select EMIO, so that I2C can be connected to the PL side for the HDMI DDC connection.

3) Configure the clocks. Set FCLK_CLK0 to 100MHz and FCLK_CLK1 to 142MHz. This clock is used for VDMA data reading. This is because the frequency for 1080p at 60fps is 148.5MHz, but that includes synchronization and blanking time. Since VDMA only transfers valid data, setting it to 142MHz is sufficient.

Configuring VDMA
~~~~~~~~~~~~~~~~

5) Add the VDMA IP.

.. image:: images/14_media/image6.png
      
6) Configure the basic VDMA parameters as shown in the figure below. Two interfaces are primarily involved here. The Memory Map interface uses the AXI4 interface to exchange data with the ZYNQ HP port and read image data from the PS-side DDR. The ZYNQ HP interface is a 64-bit interface, so we also set it to 64 bits here. Of course, it can be set larger, as the crossbar interconnect module can automatically convert data widths. The other interface is the Stream interface, which is the AXI4 Stream interface, mainly used to transmit image data to the HDMI interface. Since RGB data is 24 bits, the Stream Data Width is also set to 24. Frame Buffers is the number of frame buffers that can store multiple frames of images. In this experiment, only 1 frame buffer is enabled. Line Buffer Depth is similar to a FIFO buffer, measured in units of Stream Data Width. Setting it larger allows more data to be buffered.

.. image:: images/14_media/image7.png
      
1) Configure the advanced VDMA parameters. Here, enable Allow Unaligned Transfers. If not enabled, the software must align data according to the Memory Map Data Width. For example, since we set it to 64, the data must be 64-bit aligned. But with this enabled, unaligned data transfers are allowed. GenLock is used to prevent the read and write channels from accessing the same frame simultaneously, which would cause incorrect image display. Since we only have one read channel, this setting is not very significant and is only useful when configured with a write channel. There are many combination modes; refer to the VDMA manual PG020 for details.

.. image:: images/14_media/image8.png
      
8) Add the Video Timing Controller. This module is mainly used to generate video timing.

.. image:: images/14_media/image9.png
      
9) Configure the Video Timing Controller parameters (abbreviated as VTC). Enable Generation enables the output timing generation; after selecting it, the vtiming_out bus signal will appear. Enable Detection enables detection of input timing signals; if enabled, the vtiming_in bus will appear. Since this experiment is for image output, detection is not enabled.

.. image:: images/14_media/image10.png
      
10) Add the AXI4-Stream to Video Out controller.

.. image:: images/14_media/image11.png
      
11) Configure the AXI4-Stream to Video Out controller parameters. For Clock Mode, select Independent, meaning the AXI4-Stream and Video clocks are independent and asynchronous, while Common means synchronous. In this experiment, the two are asynchronous. For Timing Mode, Slave mode means the VTC is a timing slave, and the Video Out module controls timing output through clock enable. Master Mode means the VTC is the timing master and is not controlled by Video Out. Refer to the module user manual pg044 for details.

.. image:: images/14_media/image12.png

Vitis Software Development and Debugging
-----------------------------------------

1) The relevant programs have been prepared.

.. image:: images/14_media/image30.png
      
2) In the display_ctrl folder, display_ctrl.c mainly handles display control, and vga_mode.h contains timing parameters for various display resolutions.

.. image:: images/14_media/image31.png
      
In display_ctrl.c, you can modify displayPtr->vMode to change the display resolution.

.. image:: images/14_media/image32.png
      
3) The Dynclk file's main function is to configure the PLL clock output for different resolutions to generate the pixel clock.

.. image:: images/14_media/image33.png
      
4) There is an important concept to understand. Generally, we know that images have the concept of rows and columns. In the VDMA registers, these are HSIZE and VSIZE. There is also an additional STRIDE register, which can be understood as the maximum number of bytes stored per row, and it must be greater than or equal to HSIZE. Note that both HSIZE and STRIDE are measured in bytes.

.. image:: images/14_media/image34.png
      
For example: If the display resolution is 1920*1080 with 24-bit color depth (i.e., 3 bytes), then HSIZE can be set to 1920*3, VSIZE to 1080, and STRIDE to 1920*3. If the display resolution is changed to 1280*720, then HSIZE is set to 1280*3, VSIZE to 720, and STRIDE does not need to change and remains 1920*3.

5) Connect the HDMI output port to the monitor, compile and run.

Chapter Summary
---------------

This chapter introduced using VDMA to implement HDMI display. Many modules are used, and readers should study the documentation for each module, especially VDMA, VTC, and Video Out, and take time to understand them thoroughly. This experiment serves as the foundation for subsequent display experiments, so it is worth spending extra time to study.
