RS485 Experiment
================

**The Vivado project for this experiment is "rs485_test".**

This chapter introduces RS485 data transmission using the AN3485 module.

Experiment Principle
--------------------

The RS232 and RS422 experiments were introduced earlier. RS485 is similar to RS422, also using differential signal transmission, but RS485 is half-duplex, meaning that data can only be transmitted in one direction at any given time. Additionally, the RS485 interface has fewer signals than RS422, with only differential signals A and B. The signals connected to the ARM or FPGA are DE (direction select), DI (input signal TXD), and RO (output signal RXD).

.. image:: images/16_media/image1.png
      
According to the MAX3485 datasheet, for the transmit direction, when DE is 1 (i.e., output enable) and DI is 1, the differential signals A and B are 1 and 0 respectively; otherwise they are 0 and 1.

.. image:: images/16_media/image2.png
      
For the receive direction, when DE is 0 and the voltage difference between A and B is greater than or equal to +0.2V, the RO value is 1; otherwise it is 0.

.. image:: images/16_media/image3.png
      
Program Design
--------------

Since RS485 is half-duplex, we need to define a transmission protocol for handshaking. The first byte is set to 8'h55, indicating the start of a data frame, followed by the data length information. Due to the FIFO size limitation (256), the range is 1 to 255, followed by the data. The format is: start byte 8'h55 + data length + data.

The uart_tx and uart_rx modules are the same as in the RS232 experiment; only the uart_test module needs to be modified here. The designed functionality sets DE to 0 (i.e., input) in the initial state, waiting to receive data from the host computer and buffering it into a FIFO with a size of 256. Then DE is switched to 1 (i.e., output), and the received data is read from the FIFO and transmitted. Note that the buffered data excludes the start byte 8'h55 and the length information.

In the RCV_HEAD state, it checks whether the received data is "S".

.. image:: images/16_media/image4.png
      
In the RCV_COUNT state, if the data length is less than 0, it jumps to the IDLE state; if greater than 0, it enters the receive data state.

.. image:: images/16_media/image5.png
      
In the RCV_DATA state, data is written to the FIFO, the data length is checked, the RS485 direction is switched to output, and the state transitions.

.. image:: images/16_media/image6.png
      
When switching the bus state, for reliable operation, a 1ms delay is applied in the WAIT state before switching direction.

.. image:: images/16_media/image7.png
      
Next is sending the data from the FIFO. The SEND_WAIT state controls the read enable signal fifo_rden and checks whether all data has been sent. After all data is sent, it returns to the IDLE state.

.. image:: images/16_media/image8.png
