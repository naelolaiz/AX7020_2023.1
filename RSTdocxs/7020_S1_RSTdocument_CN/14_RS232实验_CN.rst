RS232 Experiment
================

**The Vivado project for this experiment is "rs232_test".**

This chapter uses the RS232 circuit of the AN3485 module to implement UART data transmission.

Module Introduction
-------------------

The ALINX AN3845 module is an RS232/485/422 communication module specifically designed for industrial field applications. It includes one RS232 interface, two RS485 interfaces, and two RS422 communication interfaces. Together with the development board, it enables remote data transmission and communication via RS232, 485, and 422. The RS232, 485, and 422 interfaces use the MAX3232, MAX3485, and MAX3490 chips respectively as level conversion chips. The module has a 40-pin female header for connecting to the development board. The RS232 interface is a standard DB9 male serial port connector that connects directly to a computer or other devices via a serial cable;
the RS485 and RS422 interfaces use terminal blocks for external connections, supporting ultra-long-distance transmission up to thousands of meters. Additionally, the RS485 and RS422 interface sections feature ±15KV ESD protection.

Program Design
--------------

The serial port described in this document refers to asynchronous serial communication, which is UART (Universal Asynchronous Receiver/Transmitter). The program in this experiment is designed to send "HELLO ALINX" to the serial port every second. If data is received on the RXD line, the received data is sent back out, implementing a loopback function.

.. image:: images/14_media/image3.png

Asynchronous Serial Communication Protocol
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A message frame starts with a low start bit, followed by 7 or 8 data bits, an optional parity bit, and one or more high stop bits. When the receiver detects the start bit, it knows that data is ready to be transmitted and attempts to synchronize with the transmitter's clock frequency. If parity checking is selected, the UART appends a parity bit after the data bits. The parity bit can be used to help with error checking. During reception, the UART removes the start and stop bits from the message frame, performs parity checking on the incoming bytes, and converts the data bytes from serial to parallel. The UART
transmission timing is shown in the figure below:

.. image:: images/14_media/image4.png
      
From the waveform, it can be seen that the start bit is low level, while the stop bit and idle state are both high level. In other words, the line is high when no data is being transmitted. Using this characteristic, we can accurately receive data — when a falling edge event occurs, we consider it the beginning of a data transmission.

Baud Rate
~~~~~~~~~

Common serial communication baud rates include 2400, 9600, 115200, etc. The transmit and receive baud rates must be consistent for correct communication. The baud rate refers to the maximum number of data bits transmitted per second, including start bits, data bits, parity bits, and stop bits. If the communication baud rate is set to 9600, the duration of one data bit is 1/9600 seconds. In this experiment, the baud rate is generated from a 50MHz clock.

Receive Module Design
~~~~~~~~~~~~~~~~~~~~~

The serial receive module uart_rx is a parameterized configurable module. The parameter "CLK_FRE" defines the system clock frequency of the receive module in MHz, and the parameter "BAUD_RATE" is the baud rate. The receive state machine state transition diagram is as follows:

.. image:: images/14_media/image5.png
      
The "S_IDLE" state is the idle state. After power-on, it enters "S_IDLE". If the signal "rx_pin" has a falling edge, it is considered the start bit of the serial data, and the state transitions to "S_START". After waiting one BIT period for the start bit to end, it enters the data bit receiving state "S_REC_BYTE". In this experiment, the data width is designed as 8 bits. After reception is complete, it enters the "S_STOP" state. In "S_STOP", it does not wait for a full BIT period — \ **it only waits for half a BIT period**\ . This is because waiting a full period might cause missing the start bit detection of the next data frame. Finally, it enters the "S_DATA" state, where the received data is sent to other modules. One important point about this module: to satisfy the sampling theorem, each data bit is sampled at the midpoint of the baud rate counter period during data reception, to avoid data errors:

.. code:: verilog

 //receive serial data bit data
 always@(posedge clk or negedge rst_n)
 begin
 if(rst_n == 1'b0)
 rx_bits <= 8'd0;
 else if(state == S_REC_BYTE && cycle_cnt == CYCLE/2 - 1)
 rx_bits[bit_cnt] <= rx_pin;
 else
 rx_bits <= rx_bits; 
 end

Note:\ **This experiment does not include parity bit design**\ .

Transmit Module Design
~~~~~~~~~~~~~~~~~~~~~~

The transmit module uart_tx design is similar to the receive module, also using a state machine. The state transition diagram is as follows:

.. image:: images/14_media/image6.png
      
After power-on, it enters the "S_IDLE" idle state. If there is a transmit request, it enters the start bit transmission state "S_START". After the start bit is sent, it enters the data bit transmission state "S_SEND_BYTE". After the data bits are sent, it enters the stop bit transmission state "S_STOP". After the stop bit is sent, it returns to the idle state. In the data transmit module, data written from the top-level module is directly passed to the register 'tx_reg', and the 'tx_reg' register simulates the serial transmission protocol under the state machine's conditional transitions for data transmission:

.. code:: verilog

 always@(posedge clk or negedge rst_n)
 begin
 if(rst_n == 1'b0)
 tx_reg <= 1'b1;
 else
 case(state)
 S_IDLE,S_STOP:
 tx_reg <= 1'b1; 
 S_START:
 tx_reg <= 1'b0; 
 S_SEND_BYTE:
 tx_reg <= tx_data_latch[bit_cnt];
 default:
 tx_reg <= 1'b1; 
 endcase
 end

Baud Rate Generation
~~~~~~~~~~~~~~~~~~~~

In the transmit and receive modules, the parameter CYCLE is declared, which is the count value for one UART cycle. The counting is performed under the 50MHz clock. Users only need to set the CLK_FRE and BAUD_RATE parameters.

Test Program
~~~~~~~~~~~~

The test program is designed so that the FPGA sends "HELLO
ALINX\\r\\n" to the serial port once per second. During non-transmitting periods, if serial data is received, the received data is directly sent to the transmit module and returned. "\\r\\n" here has the same meaning as in C language, representing carriage return and line feed.

The test program instantiates both the transmit module and the receive module, passing the parameters in, with the baud rate set to 115200.

.. code:: verilog

 always@(posedge sys_clk or negedge rst_n)
 begin
 if(rst_n == 1'b0)
 begin
 wait_cnt <= 32'd0;
 tx_data <= 8'd0;
 state <= IDLE;
 tx_cnt <= 8'd0;
 tx_data_valid <= 1'b0;
 end
 else
 case(state)
 IDLE:
 state <= SEND;
 SEND:
 begin
 wait_cnt <= 32'd0;
 tx_data <= tx_str;
 
 if(tx_data_valid == 1'b1 && tx_data_ready == 1'b1 && tx_cnt < 8'd12)//Send 12 bytes data
 begin
 tx_cnt <= tx_cnt + 8'd1; //Send data counter
 end
 else if(tx_data_valid && tx_data_ready)//last byte sent is complete
 begin
 tx_cnt <= 8'd0;
 tx_data_valid <= 1'b0;
 state <= WAIT;
 end
 else if(~tx_data_valid)
 begin
 tx_data_valid <= 1'b1;
 end
 end
 WAIT:
 begin
 wait_cnt <= wait_cnt + 32'd1;
 
 if(rx_data_valid == 1'b1)
 begin
 tx_data_valid <= 1'b1;
 tx_data <= rx_data;   // send uart received data
 end
 else if(tx_data_valid && tx_data_ready)
 begin
 tx_data_valid <= 1'b0;
 end
 else if(wait_cnt >= CLK_FRE * 1000000) // wait for 1 second
 state <= SEND;
 end
 default:
 state <= IDLE;
 endcase
 end
 
 //combinational logic
 //Send "HELLO ALINX\r\n"
 always@(*)
 begin
 case(tx_cnt)
 8'd0 :  tx_str <= "H";
 8'd1 :  tx_str <= "E";
 8'd2 :  tx_str <= "L";
 8'd3 :  tx_str <= "L";
 8'd4 :  tx_str <= "O";
 8'd5 :  tx_str <= " ";
 8'd6 :  tx_str <= "A";
 8'd7 :  tx_str <= "L";
 8'd8 :  tx_str <= "I";
 8'd9 :  tx_str <= "N";
 8'd10:  tx_str <= "X";
 8'd11:  tx_str <= "\r";
 8'd12:  tx_str <= "\n";

 endcase
 end

Experiment Test
---------------

Insert the AN3485 module into the J11 expansion port. Here we use a USB to RS232/RS485/RS422 converter device. Since many computers do not have a 9-pin serial port, we connect through a serial cable to a USB-to-serial converter device, and then connect to the computer via USB. If the computer has a serial port, it can be connected directly.

.. image:: images/14_media/image10.png
      
Find the serial port number "COM5" in the Device Manager.

.. image:: images/14_media/image11.png
      
Open the serial port debugger, select port "COM5" (choose according to your own situation), set the baud rate to 115200, select None for parity, 8 for data bits, and 1 for stop bits, then click "Open Serial Port". This software is included in the example project folder.

.. image:: images/14_media/image12.png
      
After opening the serial port, you will receive "HELLO ALINX" every second. Enter the text you want to send in the send area input box, click "Manual Send", and you can see the characters you sent being received back.
